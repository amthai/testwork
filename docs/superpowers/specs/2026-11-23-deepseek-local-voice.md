# Открытые речевые модели и DeepSeek для Proof

В исходном локальном режиме `deepseek` распознавание русских реплик выполняет GigaAM-v3 E2E CTC, озвучку — Piper с голосом Denis. Обе модели работают на CPU отдельным процессом. Сервис получает только PCM и текст для озвучки. Аудиозаписи обрабатываются в памяти. Для записи используется микрофон браузера и проверка пауз. Между браузером и Proof используется существующий HTTPS без медиапортов.

Сервер отправляет в DeepSeek Flash текст задания, переданные изображения, расшифровки и выборку кадров для вопросов и отчёта. Стандартные фразы и утверждённые вопросы озвучиваются дословно. Ответы модели проходят существующие проверки источников, цитат и лимитов уточнений. Текст для озвучки допускает замену написания терминов для произношения, расшифровка кандидата сохраняется как получена.

Выбор провайдера задаётся на сервере. Для существующих установок с одним ключом OpenAI сохраняется прежний режим. При явном выборе DeepSeek отсутствие ключа или недоступность локальной речи показывает ошибку. Автоматического обращения к другому платному провайдеру нет.

Проверка включает изоляцию сессий, передачу изображений, прерывание и завершение реплики, настоящий прогон обеих речевых моделей и отдельный живой запрос при доступном ключе и разрешении на оплату.

Первое слово у лида. Участник может перебить любую реплику голосом. Браузер сравнивает звук микрофона с воспроизводимой речью, сервер подтверждает перебивание по распознанным словам. При встречном вопросе лид отвечает по контексту разговора и возвращает слово. К показу работы, вопросам и завершению можно перейти обычной русской речью. Паузы в презентации сохраняют за участником слово. Кнопки остаются запасным способом управления.
## Ускорение голосового хода, 25 ноября

Для новых клиентов первый опрос доставляет ответ порциями через один HTTP-поток. Каждая порция содержит длину и самостоятельно декодируемый звуковой фрагмент. Основной кодек — Opus, для браузеров без поддержки используется WAV. Отмена хода останавливает все ожидающие фрагменты и сохраняет возможность перебить лида. Старый клиент получает прежний WAV. Старт и окончание слышимой реплики подтверждает браузер.

DeepSeek выбирает действие и, для перехода к обсуждению или ответа на проверочный вопрос, возвращает его план одним запросом. Сервер проверяет основания плана и лимиты до озвучки. У встречного вопроса первая законченная фраза может уйти в озвучку при поступлении текста модели. Цель — медиана до трёх секунд для коротких вопросов. Для проверки сравниваются конец тестовой речи и первый звук ответа на одних часах браузера.


Для простых вопросов о требованиях можно отправить незавершённый фрагмент в GigaAM после 384 мс тишины. Продолжение речи отменяет черновик. Распознанный законченный вопрос про бриф можно подтвердить после 544 мс тишины, остальной рассказ сохраняет порог 832 мс.

## Голос лида, 25 ноября 2026

В production текст реплик лида озвучивает SpeechKit API v3, модель LiveTTS, голос Денис в разговорном амплуа. Пользователь выбрал этот вариант после прослушивания двух одинаковых реплик. Распознавание микрофона остаётся на сервере Proof, разговор ведёт DeepSeek. В SpeechKit поступает только текст для произнесения. Ключ с областью синтеза хранится на сервере.

В версии 0.5 знакомство воспроизводилось из записи Яндекса. С версии 0.6 Денис знакомится и прощается по правилам ниже. Готовый вопрос передаётся на синтез целиком. При потоковой генерации разговорного ответа можно озвучить законченное предложение до готовности остального текста. Перебивание отменяет запрос и воспроизведение. Локальный режим Piper доступен через настройку сервера.

## Завершённый ответ и разбор по сохранённым основаниям

После окончания показа лид благодарит за рассказ и предупреждает о переходе к вопросам. Имя допустимо только из явного представления самого участника. После ответа короткий отклик связан с переходом к следующей теме или уточнению. Журнал хранит сам вопрос отдельно от произнесённой связки.

Пауза во время презентации и просьба дать подумать сохраняют слово за участником. В обсуждении завершённый ответ на прозвучавший вопрос требует следующего хода. Если классификатор оставил такой ответ без реакции, сервер даёт время на продолжение и повторно планирует ход. Начало новой речи отменяет отложенную реакцию.

В разборе модель получает короткие ссылки на источники. Если отдельные ссылки ошибочны, сервер убирает соответствующие выводы и заново собирает итог по проверенным пунктам. Если проверенных пунктов нет, участник получает явно обозначенный разбор по журналу с привязкой к реальным ответам.

## Знакомство с Денисом и окончание звонка

Денис здоровается и спрашивает, как обращаться к участнику. На этом останавливается и ждёт ответ. Знакомство можно пропустить, сразу начать показ или задать встречный вопрос. Имя, произнесённое при знакомстве, хранится в этой защите и остаётся доступным при переподключении и в длинном разговоре. Затем Денис передаёт слово и объясняет формат вопросов.

При завершении Денис формулирует короткое личное прощание по разговору. Голосовой переход продолжает поддерживать перебивание. С версии 0.7 кнопка «Покинуть звонок» сразу выключает захват и воспроизведение. При потере звука или связи ожидание ограничено, сохранённый разговор доступен для разбора.
