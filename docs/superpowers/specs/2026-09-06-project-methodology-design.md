# Проектная методология Proof

Дата: 2026-09-06

## Цель

Перенести в Proof переносимое ядро методологии UISamurai: проектные правила, разделение текущей документации и истории, knowledge-журнал, реестр багов, QA-процесс и changelog.

Методология должна помогать быстро восстанавливать контекст проекта и не должна превращаться в копию продуктовых или инфраструктурных данных UISamurai.

## Объём

Входит:

- `AGENTS.md` с универсальными и Vite/React/TypeScript-правилами;
- `README.md` и `docs/README.md` как навигация;
- `docs/product/` для scope и текущего пользовательского поведения;
- `docs/technical/` для стека, локального запуска и deployment-контуров;
- `docs/qa/` для процесса и ручных кейсов;
- `docs/knowledge/` для датированных записей решений, фиксов, тестов и инфраструктурных действий;
- `CHANGELOG.md` для краткой истории заметных изменений.

Не входит:

- перенос реальных записей и истории UISamurai;
- копирование его доменов, путей, production-команд, секретов и продуктовых ограничений;
- добавление `.agents/skills` без конкретной потребности Proof;
- изменение пользовательской логики приложения.

## Архитектура документации

`docs/` остаётся единственным корнем документации. Существующий путь `docs/superpowers/specs/` сохраняется, чтобы не ломать текущий workflow спецификаций. Новые разделы добавляются рядом, без второго каталога `specs/`.

Постоянные документы описывают текущее состояние. Knowledge-запись фиксирует контекст и мотивацию конкретной работы. `CHANGELOG.md` содержит только краткие заметные изменения.

## Workflow изменения

1. Прочитать `AGENTS.md`, `docs/README.md` и связанные product/technical/spec документы.
2. Для заметного изменения зафиксировать scope и решение в `docs/superpowers/specs/`.
3. Внести изменение.
4. Синхронизировать постоянную документацию, если поменялось текущее поведение.
5. Запустить `npm run build` и релевантный ручной QA-сценарий.
6. Создать одну knowledge-запись и добавить её в `knowledge/INDEX.md`.
7. Для бага обновить `knowledge/bugs.md`.
8. Для пользовательского изменения обновить `CHANGELOG.md`.

## Безопасность и границы

- Секреты остаются только в локальном окружении или защищённом runtime.
- `OPENAI_API_KEY` нельзя помещать в Vite client bundle.
- Mock realtime явно обозначается как mock.
- Инфраструктурные значения Proof не входят в переносимое ядро методологии и документируются отдельно.
- Удаление файлов, изменение production или расширение MVP требуют отдельного решения, а не неявного следования шаблону.

## Критерии готовности

- Новый участник понимает, где искать продукт, технические решения, QA и историю.
- Агент получает локальные правила до изменения кода.
- Для значимой работы есть воспроизводимая запись с результатом проверки.
- Текущие спецификации не потеряны и не продублированы.
- Документация не содержит данных, скопированных из UISamurai по ошибке.
