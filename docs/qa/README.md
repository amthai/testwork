# QA-процесс

Перед завершением изменения обязательны npm test, npm run build и проверка изменённого UI в браузере. Для серверных изменений проверяются изоляция владельцев, лимиты, lifecycle, ошибки провайдера и хранение. Перед публикацией также npm audit --audit-level=high и candidate-контейнер.

Тестовый провайдер допустим только в tests/ как управляемая зависимость автоматических проверок. Он не доказывает работоспособность внешней интеграции. Полный live-прогон должен подтвердить реальное аудио, получение кадров, транскрипцию и индивидуальный разбор.

Статусы: planned — не проверено; passed — проверено; failed — дефект; blocked — внешнее ограничение. Любой блокер фиксируется прямо, без подмены успешным результатом.

Список сценариев — test-cases.md. Датированные результаты и артефакты — в knowledge-журнале; скриншоты локальной QA — в игнорируемом output/playwright/.
