# QA-процесс

QA-документация фиксирует не только наличие проверки, но и фактический результат, окружение и известные ограничения.

## Минимальный gate

Перед завершением изменения:

1. Запусти `npm run build`.
2. Проверь затронутый пользовательский сценарий в браузере.
3. Проверь responsive и keyboard-поведение, если затронут интерфейс.
4. Проверь, что mock-интеграция не описывается как production-интеграция.
5. Запиши результат в knowledge-журнал, если работа была значимой.

## Статусы кейсов

- `planned` — кейс сформулирован, но ещё не прогнан;
- `passed` — проверка прошла;
- `failed` — найден дефект;
- `blocked` — проверку нельзя завершить из-за внешнего ограничения.

Результаты конкретного прогона не переписывают историю молча: при существенном результате добавляй датированную запись в `docs/knowledge/entries/`.
