# Ответ на просьбу начать показ

В расшифровке рабочей сессии сохранились повторные просьбы разрешить начать и проверка присутствия собеседника. В журнале HTTP после просьб приложение переходило от ожидания ответа к слушанию. Записи начала воспроизведения для этих ответов отсутствовали. Точное решение языковой модели в этой сессии не сохранялось.

Регрессионный тест воспроизвёл тишину при выборе моделью действия listen. После исправления сервер сразу передаёт в озвучку ответ на самостоятельную просьбу начать или проверку связи. Для контекстных формулировок уточнены инструкции модели. Цитаты внутри рассказа остаются частью презентации. При знакомстве имя Денис может принадлежать самому участнику.

Тест проходит через распознавание, обработку реплики, получение аудио и подтверждение воспроизведения с тестовыми провайдерами.

На VPS в отдельной базе GigaAM распознал синтетические голосовые вопросы о начале рассказа и присутствии Дениса. Кандидат выдал ожидаемый ответ на каждый вопрос. Проверены WAV, декодирование потока Opus и подтверждения начала и конца воспроизведения. Для этой проверки звук синтезировал Piper. Все 94 теста и сборка прошли. Аудит сообщил о четырёх предупреждениях средней серьёзности.

Исправление опубликовано в версии 0.8.1 в 23:54 по Чите. На рабочем сайте проверены готовность и конфигурация DeepSeek и Яндекс LiveTTS. [Журнал релиза](../../../../deployment-report.md)
