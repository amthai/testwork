# Голос Яндекса в звонках Proof 0.5.0

После [сравнения одинаковых реплик](2026-11-25-yandex-piper-listening.md) пользователь выбрал голос Денис в разговорном амплуа. В production вопрос формируется в DeepSeek, а текст для озвучки передаётся через SpeechKit API v3 в LiveTTS. Микрофон распознаёт GigaAM на сервере Proof. Информация о передаче текста отображается при подготовке звонка.

В образ вошла выбранная запись приветствия длительностью 21,3 секунды. Готовые вопросы отправляются на синтез целиком. Для разговорных ответов поддерживается начало озвучки до конца генерации текста. Сервис передаёт звук порциями. Перебивание отменяет запрос синтеза и останавливает воспроизведение.

## Проверка

- Сборка и 86 автоматических тестов прошли. Покрыты разрыв JSON между сетевыми пакетами, несколько PCM-порций, совместимость с клиентом WAV, ошибка после начала передачи и выдача приветствия без запроса в облако.
- Во встроенном браузере с тестовым микрофоном вопрос «Сколько времени отводится на задание?» прервал приветствие. Работали настоящий GigaAM и LiveTTS. Для воспроизводимости использовали сохранённый ответ DeepSeek на тестовый бриф. Браузер начал воспроизводить «Четыре часа. Это указано в брифе» через 1,69 с после окончания тестовой реплики и вернулся к прослушиванию. Время генерации нового текста DeepSeek в этот опыт не входило.
- На отдельном экземпляре релизного образа VPS воспроизвели готовое приветствие и подтвердили переход к презентации. В другом ходе для новой реплики с действующим серверным ключом первый фрагмент Opus стал доступен через 304 мс с момента запроса. Прерывание запущенного звука завершило поток маркером отмены. Это один замер озвучки.
- Выполнили две проверки отсутствия активных звонков и отчётов. Создали резервную копию SQLite. Production сообщил выбранные провайдеры DeepSeek и Яндекс. [Отчёт о публикации](../../../../deployment-report.md)
