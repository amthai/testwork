# Реальная интеграция Proof и подготовка к запуску

## Контекст

Пользователь попросил заменить демонстрационный созвон полноценным продуктовым сценарием и предоставил OpenAI API-ключ. Старые ограничения mock-MVP пересмотрены в новой спецификации. Ключ настроен в игнорируемом .env.local с правами 0600; значение в журнале, исходниках и сборке отсутствует.

## Решение и реализация

- Fastify-сервер создаёт реальный OpenAI WebRTC call; серверный sideband управляет диалогом, принимает завершённые транскрипты, подтверждает кадры и завершает удалённый звонок. В браузер API-ключ не передаётся.
- RealtimeTransport заменил mock; добавлены состояния ошибок, восстановления соединения и блокировки воспроизведения аудио.
- Кадры выбранного экрана ограничены по размеру и частоте. UI считает кадр переданным только после подтверждения провайдера. В Realtime остаётся ограниченное число изображений; SQLite хранит ограниченную выборку.
- Итоговый отчёт формируется через Responses API и проверенную структуру. Основания с неизвестными ID отбрасываются; при недостатке стенограммы нет шаблонной похвалы или выдуманного разбора.
- SQLite сохраняет стенограмму, выборку кадров, результат и реестр удалённых звонков. Реализованы история на текущем устройстве, экспорт Markdown, явное удаление и retention 7 дней.
- Для ограниченного запуска: код приглашения в production, HttpOnly/SameSite/Secure cookie, изоляция владельцев, проверка Origin, rate limits, лимиты числа сессий и длительности. Одна серверная реплика; нет аккаунтов, оплаты и межустройственной истории.
- Реестр удалённых call ID переживает рестарт и удаляется только после подтверждённого hangup. Сервер завершает забытые звонки по heartbeat и сроку; незавершённые попытки восстанавливаются как interrupted.
- Добавлены Docker runtime с persistent volume, запуск без root с read-only filesystem, CI для тестов/сборки/audit/образа, безопасные команды проверки OpenAI и подготовки кода доступа.
- Обновлены продуктовые ограничения, техническая документация, QA и CHANGELOG. Исторические mock-спецификации помечены как заменённые.

Основные изменения: server/, src/lib/realtime.ts, src/lib/session.ts, src/lib/api.ts, src/hooks/use-screen-context.ts, src/App.tsx, страницы preflight/call/feedback/history, Dockerfile, compose.yaml, tests/server.test.ts.

## Дефекты, выявленные и исправленные при проверке

- BUG-001: счётчик кадров мог подтверждать только отправку в сокет, а не принятие OpenAI. Теперь ожидание подтверждения/ошибки с таймаутом; регрессионные тесты.
- BUG-002: credit_balance_exhausted отображался как временная занятость. Теперь отдельная понятная ошибка недостатка средств, включая исчерпание во время звонка.
- BUG-003: время неудачного подключения продолжало расти в истории. endedAt фиксируется при сбое/прерывании; регрессионный тест.
- BUG-004: переход между экранами сохранял старую вертикальную прокрутку. Восстановление начала экрана и очистка session hash при выходе; подтверждено в мобильном браузере.
- BUG-005: JSON Content-Type на POST без тела приводил к отказу Fastify. Заголовок добавляется только при наличии JSON body; серверные и браузерные сценарии проходят.

Дополнительно защищены повторный запрос отчёта во время финальной транскрипции, повторный hangup после сетевой ошибки и устаревшие media-запросы при уходе со страницы.

## Проверки и фактический результат

- npm test: 23 passed, 0 failed. Провайдер в автоматических тестах заменён только внутри tests/, это не live QA.
- npm run build: passed, включая strict TypeScript клиента и сервера. Есть неблокирующее предупреждение о frontend chunk >500 kB.
- npm audit --omit=dev: 0 уязвимостей.
- docker build -t proof:live-candidate .: passed. Production candidate проверен на отдельном QA-томе: код доступа, Secure cookie, readiness, восстановление авторизации после рестарта. /.env.local отдаёт 404; в runtime образе такого файла нет.
- Chromium: preflight, реальные media API с синтетическими QA-устройствами, ошибка квоты, история, недостаточный контекст, удаление попытки; desktop 1440 и mobile 375.
- Контрольный отчёт: отдельный browser route fixture с явной пометкой, визуально проверены карточки и стенограмма, переходы по основаниям и содержимое скачанного Markdown. Перехват затем снят; runtime не содержит фикстуры.
- Проверка файлов Git и клиентской/серверной сборки не обнаружила предоставленный ключ; .env.local имеет mode 0600. Build, DB и QA-артефакты игнорируются. git diff --check проходит.

Подробная матрица результатов и непроверенных сценариев: docs/qa/test-cases.md. Скриншоты и контрольный Markdown оставлены локально в игнорируемом output/playwright/.

После проверки удалены только созданные для QA контейнер proof-live-candidate-20260906, его отдельный том proof-live-candidate-data-20260906 и временный cookie-файл. QA-том удалён без восстановления; пользовательские сессии в локальном data/ и production не затронуты. Локальный candidate-образ оставлен для повторной проверки.

## Блокер выпуска

Ключ принят OpenAI: список моделей доступен. Однако настоящие платные запросы, включая попытку созвона, отклонены с credit_balance_exhausted / insufficient_quota. Успешное получение краткоживущего токена не означает, что платный разговор доступен.

Код интеграции реализован, но живое аудио, понимание показанного экрана и качество индивидуального AI-разбора ещё не подтверждены. Статус blocked относится к полному live QA и выпуску, а не к результатам локальных тестов.

Необходимо пополнение OpenAI API-баланса, затем полный live gate из QA-документа и подтверждённая публикация на VPS. Денежные операции, новый production-деплой и Git-коммит не выполнялись. Публичный сайт остаётся на предыдущем mock-релизе; deployment-report.md отделяет его от нового локального candidate.

Перед широким открытым запуском остаются отдельные задачи: полноценные аккаунты и управление доступом, нагрузочные и кросс-браузерные проверки, backup/restore на целевом окружении. Это не заявлено как завершённое.
