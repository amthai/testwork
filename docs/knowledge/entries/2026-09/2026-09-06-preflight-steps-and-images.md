# Три шага подготовки, фото задания и нейтральные ошибки

## Контекст

Пользователь попросил разделить длинную подготовку на задание, подключение устройств и советы, добавить фотографии задания и убрать сообщение о внутреннем балансе OpenAI. Существующая реальная интеграция и методология дизайн-лида сохранены.

## Решение

- Трёхэтапная подготовка с progress-stepper, фокусом заголовка и одной основной кнопкой внизу. На первом шаге она анализирует материалы, после анализа ведёт к устройствам. Начало разговора — только на третьем. Прежний визуальный язык сохранён.
- Черновик текста/фото живёт в App; переход назад не уничтожает материалы, анализ и media streams. Изменение материалов сбрасывает анализ и блокирует последующие шаги. Перезагрузка вкладки сбрасывает черновик: в localStorage частные данные не пишутся.
- До трёх JPG/PNG/WebP по 10 MiB: drag/drop, выбор файлов, ограничение, просмотр в native dialog, удаление, повтор. Изображения перекодируются в JPEG до 2048 px / 1.2 млн символов data URL, без исходных метаданных.
- API принимает фото-only и смешанный ввод, проверяет запрос, контейнер JPEG и лимиты до провайдера. Responses получает настоящие input_image. Источники распознавания и точные цитаты проверяются сервером; пользователь может проверить OCR до созвона.
- После анализа сохраняются только метаданные/извлечённый контекст. Raw изображения не попадают в SQLite, session polling и Realtime-инструкции. Контекст входит в дальнейшие вопросы, разбор и Markdown; фото задания не считаются доказательством готовой работы. Сохранённые старые сессии совместимы через defaults.
- BUG-009: providerError, HTTP и чтение старых сессий дают нейтральную временную недоступность, сохраняя код quota. Убрано ложное обещание сохранённой сессии при отказе анализа до звонка. Ошибка не заменяется фиктивным результатом.
- Лимит /api/briefs — 3.7 MB, других API — 400000 bytes; локальные host Nginx-шаблоны подготовлены к 4 MiB. Production не менялся.

## Ограничения и продолжение

Живой OCR/диалог/качество советов не проверялись и не объявлены готовыми по результатам fixtures. Платных API-запросов, коммитов и публикации не было. На production остаётся предыдущая версия. Перед релизом: доступный API, живой прогон с реальными фото, nginx -t с новым лимитом и HTTPS-upload.

Проверка quote подтверждает согласованность с OCR-текстом, не точность распознавания пикселей; это явно отражено в интерфейсе/отчёте. Очень длинное или нечитаемое задание может требовать более чётких фото или введённого текста. JPEG guard ограничивает контейнер и размеры, полная читаемость проверяется провайдером. Bundle-size предупреждение Vite остаётся известным, сборку не блокирует.
