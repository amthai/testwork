# Product overview

## Назначение

Proof помогает дизайнеру потренироваться защищать тестовое задание так, как это происходит на настоящем интервью: открыть макет, говорить вслух, объяснять решения и отвечать на уточняющие вопросы.

## Основной сценарий

Пользователь проходит четыре состояния:

1. Landing — понимает ценность и начинает тренировку.
2. Preflight — проверяет микрофон и демонстрацию экрана.
3. Call — презентует работу AI-дизайн-лиду в формате созвона.
4. Feedback — получает краткий результат, сильную сторону и направление для улучшения.

В MVP пользователь не управляет внутренними этапами презентации отдельными кнопками. Основные действия — начать созвон и завершить его.

## Текущее поведение

- микрофон запрашивается через `getUserMedia({ audio: true })`;
- экран запрашивается через `getDisplayMedia({ video: true })`;
- расшаренный экран показывается в preview;
- во время созвона кадры экрана временно собираются в памяти примерно раз в пять секунд;
- realtime-транспорт сейчас mock-адаптер, поэтому приложение не должно сообщать о реальном подключении OpenAI;
- после завершения пользователь видит прототипный feedback.

## Принципы опыта

- Разговор и голос — главный сценарий, а не управление панелью.
- Интерфейс должен быть спокойным и похожим на привычный видеозвонок.
- Ошибки разрешений объясняются человеческим языком и допускают повторную попытку.
- Экран пользователя не сохраняется как непрерывное видео.
