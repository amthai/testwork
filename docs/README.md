# Документация Proof

Это единая точка входа в документацию проекта.

Документы разделены по назначению:

| Раздел | На какой вопрос отвечает |
|---|---|
| `product/` | Что строим, для кого и что входит в текущий scope |
| `technical/` | Как проект устроен, запускается и деплоится |
| `qa/` | Как проверять пользовательские и технические сценарии |
| `superpowers/specs/` | Утверждённые спецификации заметных изменений |
| `knowledge/` | Что меняли, почему приняли решение и как проверили |
| [`../CHANGELOG.md`](../CHANGELOG.md) | Краткая история заметных изменений для пользователя |

## Product

- [`overview.md`](product/overview.md) — продукт и текущий пользовательский поток;
- [`out-of-scope.md`](product/out-of-scope.md) — ограничения MVP.

## Technical

- [`stack.md`](technical/stack.md) — стек, границы и структура исходников;
- [`setup-local.md`](technical/setup-local.md) — локальная разработка и переменные окружения;
- [`deployment.md`](technical/deployment.md) — контейнерная сборка, healthcheck и production-контур.

## QA

- [`README.md`](qa/README.md) — правила проверки;
- [`test-cases.md`](qa/test-cases.md) — ручные тест-кейсы для текущего MVP.

## Specs

- [`superpowers/specs/`](superpowers/specs/) — существующие и новые дизайн-спецификации. Они сохраняют текущий рабочий путь проекта и не переносятся в отдельный дублирующий каталог.

## Knowledge journal

- [`knowledge/README.md`](knowledge/README.md) — правила ведения журнала;
- [`knowledge/INDEX.md`](knowledge/INDEX.md) — новые записи сверху;
- [`knowledge/bugs.md`](knowledge/bugs.md) — реестр багов;
- [`knowledge/_template.md`](knowledge/_template.md) — шаблон записи.

## Как синхронизировать документы

1. Измени постоянный документ, если поменялось текущее поведение проекта.
2. Для заметного решения, фикса, фичи, теста или инфраструктурной работы создай одну knowledge-запись.
3. Добавь запись в начало `knowledge/INDEX.md`.
4. Для бага синхронно обнови `knowledge/bugs.md`.
5. Если изменение заметно пользователю, добавь краткий пункт в корень `CHANGELOG.md`.

Журнал не заменяет текущую документацию: он хранит контекст и историю, а не второй вариант спецификации.
